# 식당 납품 예정과 완료 보고 시나리오

## 범위

창고에서 하위 식당으로 식자재를 납품하는 업무를 다룬다. 담당자는 납품 예정을 등록할 수 있으며, 현장에서 작업을 마친 뒤 실제 수행 결과를 보고한다.

현장 담당자가 물품과 수량을 확인하고 최종 결정을 내린다. 시스템은 계획과 보고된 결과를 기록한다. 전산재고가 실제 재고와 항상 일치한다고 전제하지 않는다.

이 문서는 논의한 시나리오를 보존한 기획 초안이다. 합의한 업무 방향과 제안·미정 사항을 구분하며, 현재 구현 계약으로 취급하지 않는다.

아래 흐름은 식당에 인계한 뒤 완료 보고하는 것을 잠정 기준으로 작성했다. 완료의 기준을 창고 반출로 정할지 식당 인계로 정할지는 아직 미정이다. 식당 내부의 재고와 조리 소비는 이번 범위에 포함하지 않는다.

## 합의한 업무 사실과 규칙

- 납품 예정은 특정 식당에 어떤 상품을 얼마나 납품할 계획인지 나타낸다.
- 현장 담당자가 실제 수행할 내용을 최종 결정한다. 예정 수량과 실제 납품 수량은 다를 수 있다.
- 예정 등록 없이 먼저 납품한 뒤 완료 결과를 보고할 수 있다.
- 예정 없는 완료 보고를 접수하기 위해 예정을 소급해서 만들지 않는다.
- 완료 보고는 예정한 내용이 아니라 담당자가 실제로 수행했다고 보고한 결과다.
- 하나의 납품 예정에 대한 전체 결과는 한 번에 보고한다. 여러 차례로 나누어 완료 보고하지 않는다.
- 완료 보고를 접수하면 해당 예정은 마감한다. 예정 대비 부족한 수량을 미납 잔량으로 이월하지 않는다.
- 추가로 수행한 납품은 별도 건으로 취급한다.

## 납품 예정 등록

담당자는 납품할 식당과 상품별 예정 수량·단위를 등록한다. 시스템은 누가 언제 어떤 계획을 등록했는지 기록한다.

예를 들어 A식당에 당근 10kg과 양파 5kg을 납품할 계획이라면 하나의 예정에 두 상품과 각각의 수량을 기록한다.

예정은 현장 작업에 참고할 계획이다. 예정 등록 자체가 물품의 실재, 재고 예약, 실제 반출 또는 납품 완료를 의미하지 않는다. 예정의 수정·취소와 이력 보존 방식은 아직 정하지 않았다.

## 납품 완료 보고

담당자는 작업을 마친 뒤 다음 결과를 보고한다.

- 어느 식당에 납품했는지
- 어떤 상품을 얼마나 납품했는지와 수량 단위
- 해당 물품을 창고의 어느 위치에서 얼마나 반출했는지
- 기존 예정에 따른 결과라면 어느 예정의 결과인지

시스템은 보고 담당자와 보고 접수 시각을 기록한다. 보고 시각과 실제 수행 시각을 동일시하지 않는다. 실제 수행 시각을 별도로 기록할지는 미정이다.

한 상품을 여러 위치에서 가져왔다면 위치별 반출 내역을 구분한다. 예를 들어 당근 7kg을 납품하면서 위치 A에서 4kg, 위치 B에서 3kg을 반출할 수 있다.

식당 인계까지 다루는 현재 초안에서는 납품 수량과 반출 수량을 구분한다. 두 수량의 차이를 허용할지, 운송 중 손실이나 미인수 물품을 어떻게 처리할지는 아직 정하지 않았다.

## 보고 접수와 재고 반영 — 초안

시스템은 보고의 필수 정보와 수량 관계 등 접수 조건을 검증한다. 담당자의 업무 판단과 시스템의 보고 검증은 구분한다. 보고가 거절되더라도 이미 발생한 현장 작업이 취소되는 것은 아니다.

예정 수량보다 적게 납품했다는 이유만으로 완료 보고를 거절하지 않는다. 다만 예정에 없는 상품·대체 상품·예정 초과 수량·다른 납품처를 보고한 경우의 구체적인 접수 정책은 미정이다.

현재 초안에서는 다음 처리를 제안한다.

- 예정 등록으로 현재고를 변경하지 않는다.
- 완료 보고를 접수할 때 보고된 위치별 반출 수량을 전산재고에 반영한다.
- 보고 전체의 접수와 재고 반영은 함께 성공하거나 함께 실패한다.
- 일부 내역만 접수하거나 거절된 보고를 근거로 재고를 변경하지 않는다.

전산재고가 보고된 반출 수량보다 적을 때 보고를 접수할지, 어떤 조정을 함께 처리할지는 후속 결정 사항이다. 재고 반영 후 전산재고와 실제 재고가 일치한다고 보장하지 않는다.

## 시나리오

### 1. 예정대로 납품한 경우

1. 담당자가 A식당에 당근 10kg을 납품할 예정을 등록한다.
2. 현장 담당자가 물품을 확인하고 위치 A에서 당근 10kg을 반출하여 A식당에 납품한다.
3. 담당자가 해당 예정에 연결하여 전체 납품 결과를 보고한다.
4. 시스템은 접수 조건을 검증하고 완료 보고를 접수한다.
5. 현재 재고 반영 제안에 따라 위치 A의 반출 수량 10kg을 전산재고에 반영하고, 해당 예정을 마감한다.

### 2. 예정 수량보다 적게 납품한 경우

1. A식당에 당근 10kg을 납품할 예정이 등록되어 있다.
2. 현장 담당자가 상황을 확인하고 7kg을 납품하기로 결정하여 수행한다.
3. 담당자가 실제 납품 수량 7kg과 위치별 반출 내역을 보고한다.
4. 시스템은 완료 보고를 접수하고, 현재 제안에 따라 반출 수량을 전산재고에 반영한다.
5. 해당 예정은 마감한다. 예정 10kg과 보고 7kg의 차이 3kg은 확인할 수 있지만, 후속 납품 의무로 남기거나 다음 건을 자동으로 만들지 않는다.

### 3. 예정 없이 먼저 납품한 경우

1. 현장 담당자가 A식당의 요청을 받아 당근 7kg을 납품한다.
2. 담당자가 예정과 연결하지 않고 납품처, 상품, 수량과 위치별 반출 내역을 보고한다.
3. 시스템은 예정이 없다는 이유만으로 보고를 거절하지 않고 접수 조건을 검증한다.
4. 완료 보고를 접수하고, 현재 제안에 따라 반출 수량을 전산재고에 반영한다.

### 4. 여러 위치에서 반출한 경우

1. 담당자가 A식당에 납품할 당근을 위치 A에서 4kg, 위치 B에서 3kg 가져온다.
2. A식당에 당근 7kg을 납품한다.
3. 담당자는 하나의 완료 보고 안에 납품 수량 7kg과 두 위치의 반출 내역을 함께 제출한다.
4. 시스템은 전체 보고를 접수하고, 현재 제안에 따라 위치 A에 4kg, 위치 B에 3kg의 반출을 반영한다.

이 사례는 하나의 완료 보고에 여러 반출 위치를 기록하는 경우다. 하나의 예정을 여러 차례로 나누어 완료 보고하는 경우가 아니다.

### 5. 마감 후 추가로 납품하는 경우

1. 당근 10kg 예정에 대해 7kg을 납품하고 완료 보고까지 마쳤다.
2. 이후 A식당에 당근 3kg을 추가로 납품하기로 결정한다.
3. 추가 납품은 새로운 예정으로 등록하거나, 먼저 수행한 뒤 별도의 완료 보고로 기록한다.
4. 앞선 완료 보고를 수정하거나 마감된 예정에 두 번째 완료 보고를 연결하지 않는다.

### 6. 잘못 보고한 내용을 정정하는 경우 — 제안

1. 담당자가 당근 7kg을 납품했다고 보고했고 시스템이 접수했다.
2. 이후 실제 수행 결과는 6kg인데 보고를 잘못 작성했다는 사실을 확인한다.
3. 담당자가 기존 보고에 대한 정정을 요청한다.
4. 입고와 같은 정정 원칙을 적용한다면, 시스템은 이전 판을 보존하고 전체 내용을 담은 새 판을 접수한다.
5. 재고 반영 내용도 달라진다면 기존 반영과 정정 결과 사이의 차이를 함께 처리한다.

정정 허용 범위와 추가 전용 판 저장 방식은 출고에 적용할 제안이다. 새로운 납품을 수행한 경우에는 정정을 사용하지 않는다.

## 예정과 실제의 차이

예정 대비 부족한 수량이 있다는 사실과 앞으로 추가 납품할 의무가 있다는 것은 구분한다.

당근 10kg 예정에 대해 7kg을 납품하고 마감했다면 두 수량은 각각 남지만 미납 잔량 3kg은 생성하지 않는다. 예정 변경을 허용할 경우 어느 시점의 예정과 비교할지, 같은 상품을 여러 예정 항목으로 구분할 경우 어떤 항목끼리 비교할지는 후속 결정한다.

## 후속 결정 사항

- 완료 기준: 창고 반출 또는 식당 인계
- 식당 인계 기준일 경우 반출부터 보고까지의 재고 반영 지연 처리
- 전산재고보다 많은 수량을 반출했다고 보고한 경우의 접수·조정 방식
- 전량 미납 시 0수량 결과로 마감할지 예정 취소로 처리할지
- 예정에 없는 상품, 대체 상품, 예정 초과 수량 및 다른 납품처를 보고한 경우의 처리
- 예정 수정·취소, 변경 이력 보존과 예정 대비 비교 기준
- 반출 수량과 납품 수량의 관계, 운송 손실·미인수 물품의 처리 범위
- 보고 정정의 허용 범위와 추가 전용 판 저장 원칙의 적용
- 잘못 연결한 예정의 정정, 예정 없는 납품의 업무 중복 판정 기준
- 상황별 필수 정보, 정정 사유와 실제 수행 시각의 기록 여부
