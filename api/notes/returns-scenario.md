# 반송과 반품 시나리오

## 범위

창고가 공급사에서 받은 물품을 돌려보내거나, 식당을 목적으로 반출했던 물품이 창고로 돌아오는 업무를 다룬다. 물품이 어느 단계에서 돌아가는지에 따라 다음 세 가지를 구분한다.

1. 인수하지 않기로 결정한 물품을 공급사에 실제로 돌려보내는 `입고 반송`
2. 이미 인수하여 재고로 관리하던 물품을 공급사에 돌려보내는 `재고품 공급사 반품`
3. 식당을 목적으로 출고했던 물품을 창고에서 다시 받는 `납품처 반품 입고`

식당 내부에서 그 물품을 어떻게 보관하거나 사용했는지는 다루지 않는다. 납품처 반품은 창고가 반환 물품을 실제로 받는 시점부터 다룬다.

## 공통 업무 사실

- 반송 또는 반품하기로 결정한 사실과 물품을 실제로 주고받은 사실은 구분한다.
- 실제 처리 결과는 담당자가 작업을 마친 뒤 보고한다.
- 원래의 인수 또는 출고 기록을 수정하여 반송·반품을 표현하지 않는다.
- 어떤 원거래와 물품에서 비롯된 처리인지 추적할 수 있어야 한다.
- 실제로 재고가 증감하는 경우 보고 접수와 재고 반영은 함께 성공하거나 함께 실패한다.
- 반송·반품 보고를 정정할 때 기존 판을 보존하고 새 판과 재고 차이를 반영한다.

## 입고 반송

최초 인수 보고에서 반송하기로 결정한 수량은 창고 재고에 들어오지 않는다. 담당자가 그 물품을 공급사에 실제로 인계한 뒤 반송 완료 결과를 보고한다.

보고에는 공급사, 원래 인수 보고의 항목, 실제 반송 수량과 단위, 처리 담당자, 완료 시각을 포함한다. 필요한 경우 운송장 번호나 인계 근거를 함께 기록할 수 있다.

- 실제 반송 수량은 0보다 커야 한다.
- 누적 반송 완료 수량은 현재 유효한 인수 보고의 반송 결정 수량을 초과할 수 없다.
- 일부만 먼저 반송하고 나머지를 나중에 반송할 수 있다.
- 반송 완료는 애초에 재고로 반영되지 않은 물품의 처리이므로 전산재고를 변경하지 않는다.
- 반송 결정 수량 전부가 실제 반송되면 남은 반송 대기 수량은 0으로 도출한다.

## 재고품 공급사 반품

이미 적재되어 전산재고에 포함된 물품을 공급사에 돌려보낼 때에는 실제 반출 위치별 수량을 보고한다.

- 공급사, 상품, 출발 위치, 실제 반품 수량과 단위, 반품 사유를 기록한다.
- 원래 인수 건을 알 수 있다면 연결할 수 있지만, 원래 인수 건을 특정할 수 없는 재고품 반품을 허용할지는 후속 설계에서 정한다.
- 보고 접수 시 해당 위치의 재고를 실제 반품 수량만큼 차감한다.
- 전산재고가 부족해도 실제 처리 결과를 보존하며 음수 재고를 허용한다.
- 공급사의 환불, 대체 납품과 정산은 이 보고만으로 성립하지 않는다.

## 납품처 반품 입고

식당을 목적으로 창고에서 반출했던 물품이 돌아오면 담당자가 도착 수량과 상태를 확인하고 처리 결과를 보고한다.

반품 입고 보고에는 원래 출고 보고 또는 식별 가능한 출고 근거, 납품처, 상품, 도착 수량, 검사 결과와 처리 결정을 포함한다. 처리 결정은 재입고, 폐기 또는 그 밖의 보류로 구분할 수 있다.

- 도착 수량은 0보다 커야 한다.
- 원출고 수량보다 많은 반품을 허용할지는 원거래 식별 정책과 함께 정한다.
- 재입고하기로 결정한 수량만 유효한 창고 위치에 적재한 뒤 재고에 더한다.
- 폐기하거나 보류한 수량을 판매 가능한 재고에 더하지 않는다.
- `도착 수량 = 재입고 수량 + 폐기 수량 + 보류 수량`이어야 한다.
- 반품 입고는 식당의 현재 재고나 소비량을 만들거나 변경하지 않는다.

## 시나리오

### 1. 반송 결정 물품을 전부 돌려보낸 경우

1. 인수 보고에서 당근 3kg을 반송하기로 결정한다.
2. 담당자가 공급사에 당근 3kg을 실제로 인계한다.
3. 반송 완료 결과를 보고한다.
4. 시스템은 원래 반송 결정과 수량을 확인하고 완료 기록을 접수한다.
5. 재고는 변경하지 않으며 남은 반송 대기 수량은 0이 된다.

### 2. 반송 결정 물품을 나누어 돌려보낸 경우

1. 반송 결정 수량 10kg 중 6kg을 먼저 공급사에 인계한다.
2. 시스템은 6kg의 반송 완료를 접수하고 남은 수량을 4kg으로 보여준다.
3. 나중에 4kg을 인계하여 별도 완료 결과로 보고한다.

### 3. 재고품을 공급사에 반품한 경우

1. 담당자가 위치 A에 적재된 양파 5kg을 품질 문제로 공급사에 돌려보낸다.
2. 공급사, 위치, 수량과 사유를 보고한다.
3. 시스템은 보고를 접수하고 위치 A의 양파 재고를 5kg 차감한다.

### 4. 납품처에서 돌아온 물품을 재입고한 경우

1. 식당을 목적으로 출고했던 당근 5kg이 창고로 돌아온다.
2. 담당자가 검사하여 4kg은 재입고하고 1kg은 폐기하기로 결정한다.
3. 재입고 4kg을 위치 A에 적재하고 반품 입고 결과를 보고한다.
4. 시스템은 보고와 위치 A의 재고 증가 4kg을 함께 반영한다.
5. 시스템은 식당 내부 재고나 사용량을 추론하지 않는다.

### 5. 반품 보고를 정정하는 경우

1. 공급사에 재고품 5kg을 반품했다고 보고하여 재고가 차감된다.
2. 실제 수량이 4kg이었음을 확인한다.
3. 담당자가 전체 결과 4kg을 담은 정정 판을 제출한다.
4. 시스템은 이전 판을 보존하고 차이 1kg을 재고에 되돌린다.

## 현재 범위에서 다루지 않는 내용

- 공급사와의 환불, 외상매입금 차감과 대체 납품 정산
- 납품처에 대한 환불과 매출 정산
- 식당 내부 재고, 보관과 소비
- 반품 운송의 배차와 운송 중 추적
- 복수 창고 사이의 반품 이동

## 개발자에게 위임하는 판단과 후속 범위

- 세 처리 유형을 하나의 반품 관리 영역에 둘지 입고·출고 사용 사례에 나눌지 여부
- 원래 인수·출고 항목을 반드시 식별해야 하는 조건
- 반송 완료 뒤 원래 인수 보고의 반송 결정 수량이 정정되는 경우의 허용 조건
- 납품처 반품의 원출고 수량 초과와 여러 차례 부분 반품을 판정하는 규칙
- 보류 재고를 별도 위치 또는 별도 재고 상태로 관리할지 여부
- 실제 완료 시각, 사유와 증빙을 필수로 요구하는 조건
