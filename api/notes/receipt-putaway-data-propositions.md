# 인수·적재 완료 보고에서 저장할 명제

## 목적

이 문서는 `initial-receipt-report-scenario.md`와 `putaway-completion-report-scenario.md`에 정리된 업무 규칙을 바탕으로, 시스템이 저장해야 할 참인 명제를 정의한다.

업무 절차에 이름이 있다는 이유만으로 별도의 객체나 상태를 만들지 않는다. 시스템이 관찰할 수 있는 것은 현장 자체가 아니라 담당자가 제출하고 시스템이 접수한 보고이므로, 저장하는 명제도 보고를 기준으로 표현한다.

이 문서에서는 기존 문서의 `인수 내역`과 `적재 결과`를 각각 `인수 보고 항목`과 `적재 완료 보고 항목`이라고 부른다.

## 저장 원칙

### 접수된 보고는 추가 전용 기록이다

- 접수된 인수 보고와 적재 완료 보고는 수정하거나 삭제하지 않는다.
- 보고에 포함된 항목도 해당 보고의 일부이므로 수정하거나 삭제하지 않는다.
- 정정은 기존 행을 변경하는 작업이 아니라 같은 논리적 보고에 새 판을 추가하는 작업이다.
- 최초 보고와 정정 보고는 서로 다른 요청으로 접수한다.
- 새 판은 자신이 바로잡는 이전 판을 식별할 수 있어야 한다.
- 각 판에는 그 판에서 접수된 전체 항목을 저장한다. 현재 내용을 알아내기 위해 여러 판의 항목을 합성하지 않는다.
- 이전 판은 현재 유효한 보고 내용에서는 제외되지만, 담당자가 당시 그렇게 보고했고 시스템이 접수했다는 사실로 남는다.

이 원칙은 인수 보고, 적재 완료 보고와 각각의 항목에 적용한다. 시스템 전체를 이벤트 저장소로 구성한다는 의미는 아니다. 재고와 상품·위치·발주 같은 다른 데이터의 저장 방식은 각 영역의 규칙으로 결정한다.

### 보고 한 판은 하나의 원자적 기록이다

- 보고 머리와 모든 항목은 함께 접수되거나 함께 거절된다.
- 정정으로 추가되는 새 판도 전체가 함께 접수되어야 한다.
- 적재 완료 보고의 접수, 입고 완료로 간주할 수 있는 결과의 성립, 재고 반영은 모두 성공하거나 모두 실패해야 한다.
- 적재 완료 보고를 정정할 때에도 새 보고 판의 접수와 그에 따른 재고 정합성 확보는 함께 성공하거나 함께 실패해야 한다.

## 인수 보고가 나타내는 명제

### 보고 단위

1. 담당자 `A`가 한 번 도착하여 하역한 물품 전체에 대한 인수 결과 `R`을 시각 `T`에 보고했다.
2. 인수 보고 `R`은 공급사 송장 `I`를 근거로 작성되었다.
3. 인수 보고 `R`에는 인수 보고 항목 `L`이 포함되어 있다.

`R` 자체가 한 번의 입하에 대한 보고이므로, 현재 범위에서는 같은 내용을 다시 나타내는 별도의 `입고` 기록을 두지 않는다.

같은 입하에 대한 논리적 인수 보고는 `공급사 + 송장 번호`로 식별한다. 이 조합은 현재 대상 업무에서 한 번의 입하를 유일하게 식별하는 업무 키다.

### 인수 보고 항목

각 인수 보고 항목 `L`은 다음 명제를 나타낸다.

1. 항목 `L`은 발주 항목 `O`를 기준으로 구분하여 보고한 항목이다.
2. 항목 `L`의 대상 상품은 `P`이다.
3. 담당자는 공급사 송장에 항목 `L`의 물품이 수량 `Q-invoiced`로 기재되어 있다고 보고했다.
4. 담당자는 항목 `L`의 물품이 수량 `Q-arrived`만큼 실제 도착했다고 보고했다.
5. 담당자는 항목 `L`의 물품을 수량 `Q-inspected`만큼 검사했다고 보고했다.
6. 담당자는 검사에서 품질 상태 `C`를 확인했다고 보고했다.
7. 담당자는 수량 `Q-accepted`를 인수하기로 결정했다고 보고했다.
8. 담당자는 수량 `Q-returned`를 반송하기로 결정했다고 보고했다.
9. 담당자는 검사 결과와 인수·반송 결정의 근거 `D`를 보고했다.

수량은 값과 단위를 함께 가진다. 같은 상품이라도 발주 항목이 다르면 서로 다른 인수 보고 항목으로 저장한다. 품질 상태와 인수·반송 결정은 서로 다른 명제이며, 한쪽에서 다른 쪽을 추론하여 저장하지 않는다.

## 적재 완료 보고가 나타내는 명제

### 보고 단위

1. 담당자 `A`가 인수 보고 `R`에서 인수한 물품 전체에 대한 적재 완료 결과 `P`를 시각 `T`에 보고했다.
2. 적재 완료 보고 `P`는 접수 당시 기준으로 삼은 인수 보고의 정확한 판 `R-n`을 가리킨다.
3. 적재 완료 보고 `P`에는 적재 완료 보고 항목 `S`가 포함되어 있다.

시스템은 적재가 진행 중이라는 보고를 받지 않는다. 따라서 별도의 `적재 중` 상태나 중간 적재 기록을 저장하지 않는다.

### 적재 완료 보고 항목

각 적재 완료 보고 항목 `S`는 다음 명제를 나타낸다.

1. 항목 `S`는 인수 보고 `R`의 특정 인수 보고 항목 `L`에 대한 적재 결과다.
2. 담당자는 `L`에서 인수한 물품을 유효한 위치 `X`에 실제로 적재했다고 보고했다.
3. 담당자는 위치 `X`에 적재한 수량이 `Q-putaway`라고 보고했다.

적재 완료 보고 항목은 상품만으로 대상을 가리키지 않고 인수 보고 항목을 식별해야 한다. 같은 상품이어도 서로 다른 발주 항목에서 비롯된 인수 보고 항목은 적재 결과에서도 계속 구분한다.

한 인수 보고 항목을 여러 위치에 나누어 적재할 수 있는지는 두 시나리오에서 확정하지 않았다. 따라서 데이터 구조는 이 문서만을 근거로 인수 보고 항목 하나와 적재 완료 보고 항목 하나의 일대일 관계를 강제하지 않는다.

## 시스템의 처리로 성립하는 명제

1. 적재 완료 보고 `P`가 접수되면, 시스템은 `P`의 각 항목을 근거로 해당 상품과 위치의 재고를 반영했다.
2. 재고 반영의 근거가 된 적재 완료 보고와 보고 항목을 식별할 수 있다.
3. 적재 완료 보고가 정정되면, 시스템은 정정된 현재 보고 내용과 이미 반영된 재고 사이의 정합성을 유지했다.

최초 인수 보고의 접수만으로는 재고가 반영되었다는 명제가 성립하지 않는다.

## 정정이 나타내는 명제

### 인수 보고 정정

1. 담당자 `A`가 기존 인수 보고 판 `R-n`을 새 판 `R-(n+1)`로 정정하여 보고했다.
2. `R-n`과 `R-(n+1)`은 같은 논리적 인수 보고에 속한다.
3. `R-(n+1)`은 자신이 바로잡는 직전 판 `R-n`을 가리킨다.
4. 현재 유효한 인수 보고 내용은 가장 최근에 접수된 판의 전체 내용이다.

### 적재 완료 보고 정정

1. 담당자 `A`가 기존 적재 완료 보고 판 `P-n`을 새 판 `P-(n+1)`로 정정하여 보고했다.
2. `P-n`과 `P-(n+1)`은 같은 논리적 적재 완료 보고에 속한다.
3. `P-(n+1)`은 자신이 바로잡는 직전 판 `P-n`을 가리킨다.
4. 현재 유효한 적재 완료 보고 내용은 가장 최근에 접수된 판의 전체 내용이다.
5. `P-(n+1)`의 접수로 재고 반영 내용이 달라진다면, 시스템은 정정된 결과와 재고의 정합성을 함께 확보했다.

정정 사유를 필수로 받을지와 현장 발생 시각을 별도로 받을지는 아직 합의된 명제가 아니므로 이 문서에서 필수 데이터로 정하지 않는다. 다만 누가 언제 각 판을 보고했는지는 각 판이 나타내는 명제의 일부다.

적재 완료 뒤 인수 보고가 정정되더라도 기존 적재 완료 보고가 당시 어느 인수 보고 판을 기준으로 작성되었는지는 바꾸지 않는다. 인수 수량이나 항목 구분이 달라져 현재 적재 완료 보고 또는 재고와 모순이 생긴다면, 그 모순을 남긴 채 인수 보고 정정만 접수할 수는 없다. 함께 필요한 적재 완료 보고 정정과 재고 정합성 확보가 모두 성공할 때 정정을 접수한다.

## 저장하지 않고 판정하거나 도출할 내용

다음 내용은 별도의 업무 사실로 저장하기보다 접수 시 판정하거나 저장된 명제에서 도출한다.

| 내용 | 취급 |
| --- | --- |
| `실제 도착 수량 = 인수 수량 + 반송 결정 수량` | 인수 보고 항목의 접수 조건 |
| 인수 보고 항목별 적재 수량 합계가 해당 인수 수량과 일치한다 | 적재 완료 보고의 접수 조건 |
| 인수한 모든 항목의 적재 결과가 포함되어 있다 | 적재 완료 보고의 접수 조건 |
| 적재 위치가 유효하다 | 적재 완료 보고의 접수 조건 |
| 전량 반송이다 | 인수 수량과 반송 결정 수량에서 도출 |
| 적재 완료 보고가 접수되어 입고가 완료되었다 | 현재 유효한 보고와 그 접수 결과에서 도출 |
| 현재 유효한 보고 판이다 | 같은 논리적 보고에 속한 판들의 선후 관계에서 도출 |
| 현장에서 적재 중이다 | 시스템이 보고받지 않는 사실 |
| 실제 반송이 완료되었다 | 현재 두 보고가 증명하지 않는 사실 |

## 관계형 데이터 구조가 보장해야 할 것

이 명제를 테이블로 옮길 때에는 다음 관계와 제약을 보장해야 한다.

- 보고의 각 접수 판을 식별할 수 있다.
- 같은 논리적 보고에 속한 판들을 묶을 수 있다.
- 각 판의 순서와 바로 이전 판을 식별할 수 있다.
- 하나의 이전 판에서 서로 다른 정정 판이 갈라지지 않는다.
- 보고 항목은 자신이 포함된 정확한 보고 판을 참조한다.
- 적재 완료 보고는 접수 당시 기준으로 삼은 정확한 인수 보고 판을 식별한다.
- 적재 완료 보고 항목은 대상 인수 보고 항목을 식별한다.
- 보고 머리와 항목에는 갱신과 삭제를 사용하지 않는다.
- 보고 정정과 재고 반영 사이의 연결을 추적할 수 있다.

구체적인 릴레이션과 열, 키, 제약은 `inbound-relational-model.md`에서 정의한다.
