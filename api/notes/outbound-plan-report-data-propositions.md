# 납품 예정·완료 보고에서 저장할 명제

## 목적과 범위

이 문서는 창고에서 하위 식당으로 식자재를 납품하는 시나리오를 바탕으로, 시스템이 저장할 명제를 정리한 기획 초안이다. 현재 구현 계약이나 확정된 릴레이션을 정의하지 않는다.

현장 담당자가 최종 판단과 작업을 수행하고 시스템에 결과를 보고한다. 시스템이 직접 관찰하는 것은 현장 자체가 아니라 접수한 보고이므로, 수행 결과는 “담당자가 그렇게 수행했다고 보고했다”는 사실로 표현한다.

현재 초안은 식당에 인계한 뒤 납품 완료를 보고하는 흐름이다. 완료의 기준을 창고 반출로 정할지 식당 인계로 정할지는 아직 미정이다. 식당 내부의 재고와 조리 소비는 이번 범위에 포함하지 않는다.

## 합의한 업무 방향

- 예정 없이 먼저 납품한 뒤 완료 결과를 보고할 수 있다. 보고를 위해 예정을 소급해서 만들지 않는다.
- 하나의 납품 예정에 대한 수행 결과는 한 번에 보고한다. 여러 차례로 나누어 완료 보고하지 않는다.
- 예정 수량과 실제 납품 수량은 다를 수 있다.
- 완료 보고를 접수하면 해당 예정은 마감한다. 차이는 확인할 수 있지만 미납 잔량으로 이월하지 않는다.
- 추가로 수행한 납품은 별도 건으로 기록한다.

## 납품 예정이 나타내는 명제

납품 예정 `E`는 다음 명제를 나타낸다.

1. 담당자 `A`가 시각 `T`에 납품 예정 `E`를 등록했다.
2. 예정 `E`의 납품 대상은 식당 `D`다.
3. 예정 `E`에는 예정 항목 `L`이 포함되어 있다.
4. 예정 항목 `L`의 대상 상품은 `P`다.
5. 예정 항목 `L`의 납품 예정 수량은 `Q`이며 단위는 `U`다.

예정 수량은 계획한 수량이다. 해당 수량이 창고에 실제로 존재하거나, 예약되었거나, 납품되었다는 뜻은 아니다.

예정의 수정·취소와 변경 이력 보존 방식은 아직 정하지 않았으므로, 예정의 판 구조는 여기서 확정하지 않는다.

## 납품 완료 보고가 나타내는 명제

### 보고 단위

1. 담당자 `A`가 시각 `T`에 납품 완료 결과 `R`을 보고했다.
2. 담당자는 보고 `R`의 물품을 식당 `D`에 납품했다고 보고했다.
3. 보고 `R`에는 납품 완료 보고 항목 `I`가 포함되어 있다.
4. 예정에 따른 납품인 경우, 보고 `R`은 납품 예정 `E`의 수행 결과다.

예정 없이 수행한 납품 보고에는 네 번째 명제가 성립하지 않는다. 이를 위해 가상의 예정을 만들지 않는다.

`T`는 보고 시각이다. 실제 반출 시각이나 식당 인계 시각과 같다고 해석하지 않는다. 실제 수행 시각을 별도로 받을지는 아직 정하지 않았다.

### 보고 항목

각 납품 완료 보고 항목 `I`는 다음 명제를 나타낸다.

1. 항목 `I`의 대상 상품은 `P`다.
2. 담당자는 상품 `P`를 수량 `Q-delivered`, 단위 `U`만큼 식당에 납품했다고 보고했다.
3. 항목 `I`에는 반출 내역 `S`가 포함되어 있다.
4. 담당자는 반출 내역 `S`에서 해당 상품을 창고 위치 `X`로부터 수량 `Q-out`, 단위 `U`만큼 반출했다고 보고했다.

납품 수량과 위치별 반출 수량은 구분한다. 예를 들어 당근 7kg을 납품하면서 위치 A에서 4kg, 위치 B에서 3kg을 가져왔다면, 납품 결과와 각 위치의 재고 반영 근거를 모두 표현할 수 있어야 한다.

반출 수량 전부가 납품 수량과 일치해야 하는지는 별도 업무 규칙이다. 운송 중 손실이나 미인수 물품을 다룰지 정하기 전에는 두 수량을 무조건 같다고 확정하지 않는다.

완료의 기준이 창고 반출로 결정되면 “식당에 납품했다고 보고했다”를 “식당을 목적지로 반출했다고 보고했다”로 바꾸고, 납품 수량과 반출 수량을 별도로 표현할 필요가 있는지 다시 검토한다.

## 예정과 완료 보고의 관계

1. 예정에 연결된 완료 보고 `R`은 예정 `E`에 대한 한 번의 전체 수행 결과다.
2. 예정 `E`에는 논리적 완료 보고가 최대 하나 연결된다.
3. 예정과 연결되지 않은 완료 보고도 존재할 수 있다.
4. 추가로 수행한 납품은 기존 보고의 정정이 아니라 별도의 완료 보고로 기록한다.

예정 항목과 보고 항목을 직접 연결할지는 아직 확정하지 않는다. 같은 상품을 예정 안에서 여러 항목으로 구분할지, 대체 상품을 허용할지에 따라 필요한 관계가 달라진다.

예정 대비 수량 차이를 계산하려면 비교할 예정과 보고의 항목 및 단위가 정해져야 한다. 예정 변경을 허용할 경우 어느 시점의 예정 내용을 비교 기준으로 삼을지도 후속 결정 사항이다.

## 정정이 나타내는 명제 — 입고 원칙 적용 제안

입고의 `receipt-putaway-data-propositions.md`에 정의된 추가 전용 보고와 전체 내용의 새 판을 저장하는 원칙을 출고에도 적용한다면 다음 명제가 성립한다. 출고에 대한 적용은 이 초안의 제안으로 구분한다.

1. 담당자 `A`가 시각 `T`에 기존 완료 보고 판 `R-n`을 새 판 `R-(n+1)`로 정정하여 보고했다.
2. 두 판은 같은 논리적 완료 보고에 속한다.
3. 새 판은 자신이 바로잡는 직전 판을 식별한다.
4. 각 판에는 그때 보고한 전체 납품 결과가 포함된다.
5. 이전 판은 당시 접수한 보고로 남고, 현재 유효한 내용은 가장 최근에 접수한 판의 전체 내용이다.

예정 한 건에 완료 보고 한 번이라는 규칙은 정정 판의 개수를 제한한다는 뜻이 아니다. 하나의 논리적 보고에 여러 정정 판이 있을 수 있다.

정정은 기존 보고의 오류를 바로잡는 행위다. 새로 수행한 추가 납품을 기존 보고에 끼워 넣는 용도로 사용하지 않는다.

## 시스템의 재고 반영으로 성립하는 명제 — 초안

현재 초안에서는 예정 등록으로 현재고를 변경하지 않고, 완료 보고 접수 시 보고된 반출 수량을 전산재고에 반영한다.

1. 시스템은 접수한 완료 보고 판 `R-n`의 반출 내역 `S`를 근거로 상품 `P`, 위치 `X`의 전산재고에 반출 수량을 반영했다.
2. 각 재고 반영의 근거가 된 정확한 보고 판과 반출 내역을 식별할 수 있다.
3. 완료 보고가 정정되어 재고 반영 내용이 달라지면, 시스템은 그 정정에 따른 재고 변경을 반영했다.

이는 시스템이 처리한 사실이다. 처리 후 전산재고와 현장 재고가 일치한다는 사실까지 증명하지는 않는다.

## 별도 사실로 저장하기보다 도출하거나 검증할 내용

| 내용 | 취급 |
| --- | --- |
| 예정 없이 수행한 납품이다 | 완료 보고에 예정 연결이 없다는 사실에서 도출 |
| 해당 예정이 완료 보고로 마감되었다 | 연결된 완료 보고의 접수 여부에서 도출 |
| 예정 대비 수량 차이 | 비교 가능한 예정·보고 항목의 수량으로 계산 |
| 차이를 미납 잔량으로 이월하지 않는다 | 업무 정책 |
| 하나의 예정에 완료 보고를 중복 접수할 수 없다 | 접수 제약 |
| 정정 보고는 추가 납품을 나타내지 않는다 | 정정의 업무 규칙 |
| 보고 접수와 재고 반영이 함께 성공한다 | 원자적 처리 규칙 제안 |
| 현장에서 피킹·운송 중이다 | 현재 보고만으로는 알 수 없는 사실 |
| 전산재고가 실제 재고와 일치한다 | 현재 보고만으로는 보장할 수 없는 사실 |

## 후속 결정 사항

- 완료 보고의 기준: 창고 반출 또는 식당 인계
- 전산재고보다 많은 수량을 반출했다고 보고한 경우의 접수·조정 방식
- 아무것도 납품하지 못한 경우의 처리: 0수량 결과 보고 또는 예정 취소
- 예정에 없던 상품, 대체 상품, 예정 초과 수량을 납품한 경우의 처리
- 예정 수정·취소와 변경 이력 보존 방식
- 예정 항목과 보고 항목의 연결 및 예정 대비 비교 기준
- 반출 수량과 납품 수량의 관계, 운송 중 손실·미인수 물품의 처리 범위
- 완료 보고의 정정 허용 범위와 추가 전용 판 저장 원칙의 적용
- 상황별 필수 정보, 정정 사유 및 실제 수행 시각의 기록 여부

이 문서만으로 미정 사항을 확정하거나 구체적인 릴레이션과 제약을 강제하지 않는다.
