# 발주 대비 부분입고: 시나리오·불변식·정책

## 문서 상태와 목적

이 문서는 현재 구현자가 요구사항과 책임 경계를 논의하기 위한 내부 설계 초안이다. 기존 요구사항을 복원한 확정 명세나 현재 동작을 보증하는 문서가 아니다.

대화에서 확인한 방향은 부분입고를 허용하고, 실제 애플리케이션 흐름을 작성하며 객체의 책임을 검증한다는 것이다. 아래의 구체적인 정책은 검토할 제안이다. 구현 시나리오를 채택하기 전에 관련 미결정을 확인한다.

목표는 발주서·입고서의 입력과 조회를 넘어, 주문 조건과 실제 수령의 차이를 처리하고 그 결과가 재고에 일관되게 반영되도록 하는 것이다. 기존 도메인 로직은 평가 대상으로 보존한다. 이 문서만으로 클래스 분리·삭제 또는 데이터 이전을 결정하지 않는다.

## 역할과 사실의 소유권

| 역할 또는 업무 | 확정·변경하는 사실 | 시스템에 맡기는 책임 |
| --- | --- | --- |
| 구매 담당자의 발주 업무 | 공급사, 품목, 주문량, 단가, 납기, 승인, 잔량 취소 | 발주 변경 조건과 취소 가능 잔량 검사 |
| 창고 담당자의 입고 업무 | 실제 인수 수량, 로트, 위치, 입고 확정·취소 | 발주 적격성, 수량·보관 조건 검사 및 재고 반영 |
| 발주 대비 수령 현황 | 발주와 유효한 확정 입고의 대조 결과 | 수령량·잔량·진행 현황 계산 |

발주는 주문 조건의 근거이고, 유효한 확정 입고 내역은 수령 실적의 근거다. 누적 수령량을 별도로 저장한다면 독립적으로 수정하는 원본이 아니라 해당 내역으로 설명·복구할 수 있는 집계값으로 취급한다.

입고가 발주 조건을 참고한다는 사실만으로 PO 전체를 변경해야 하는 것은 아니다. 반대로 서로 다른 시점의 쓰기라는 이유만으로 애그리거트를 분리하지도 않는다. 책임 구분과 DB 트랜잭션 구분은 별도의 설계 결정이다.

## 첫 범위와 정책 제안

| ID | 정책 초안 |
| --- | --- |
| P01 | 첫 범위는 기존 발주에 연결된 입고다. 승인되고 발송 상태로 기록된 발주의 미충족 품목을 대상으로 한다. 실제 공급사 전송 연동은 포함하지 않는다. |
| P02 | 수령 실적과 재고는 입고 작성 시점이 아니라 확정 시점에 반영한다. 입력 수량은 현장에서 확인한 인수 수량이다. 도착·검수·불량 수량을 따로 모델링하는 것은 후속 논의다. |
| P03 | 부분입고는 발주 품목별로 판단한다. 같은 품목이라도 발주 내 어떤 주문 항목을 충족하는지 식별해야 한다. 발주 전체 현황은 항목별 결과로부터 구한다. |
| P04 | 남은 수량은 기본적으로 추가 입고를 기다린다. 자동으로 주문량을 줄이지 않는다. 구매 담당자가 사유를 남겨 일부 또는 전체 잔량을 취소할 수 있다. |
| P05 | 첫 범위에서는 초과 입고를 차단한다. 기존 OverReceivePolicy는 보존하되 허용 정책의 소유자·예외 승인·적용 흐름을 정하기 전에는 이 시나리오에서 사용하지 않는다. |
| P06 | 확정 전에는 입고를 수정·삭제할 수 있다. 확정 후에는 수량을 직접 덮어쓰지 않는다. 잘못된 확정은 취소하고 별도 입고로 재등록한다. |
| P07 | 입고 취소는 해당 입고로 반영한 재고에 예약·이동·소비 등 후속 처리가 없는 경우에만 허용하는 것을 제안한다. 단순히 현재 재고가 충분하다는 이유만으로 허용하지 않는다. |
| P08 | 첫 범위는 한 입고의 전체 확정·전체 취소다. 하나의 항목이라도 실패하면 전체 반영을 거절한다. 부분 확정은 범위 밖이다. |
| P09 | 수량은 품목별로 합의한 기준 단위에서 비교·집계한다. 첫 구현은 동일 단위 입력으로 제한한다. BOX와 EA 등의 환산·반올림 규칙은 후속으로 정한다. |
| P10 | 전량 수령 여부와 더 받을 잔량이 없는 상태를 구분한다. 첫 범위에서는 종료 가능 여부를 계산하고, 독립적인 최종 마감 명령과 CLOSED의 의미는 확정하지 않는다. |

## 수량 정의

각 발주 항목에 대해 다음 값을 사용한다. 서로 다른 품목의 수량을 더해 발주 전체 완료 여부를 판단하지 않는다.

- Q: 승인된 주문량. 첫 범위에서는 승인 후 직접 변경하지 않는다.
- C: 사유와 함께 취소된 주문 잔량의 누계. 입고 취소 수량과 다르다.
- R: 해당 발주 항목에 연결된 확정 입고 중 취소되지 않은 인수 수량의 합계.
- O: 앞으로 받을 수 있는 미충족 수량. O = Q - C - R.

초과 입고를 차단하는 P05 아래에서는 0 ≤ C, 0 ≤ R, C + R ≤ Q, O ≥ 0이 성립해야 한다.

진행 현황은 단일 상태 하나에 모든 의미를 넣기보다 구분해 표현한다. 예를 들어 Q=100, R=60, C=40은 실제 수령 60, 잔량 취소 40, 미충족 0이다. 이를 전량 수령 100으로 표현하지 않는다. 발주 전체의 종료 가능 여부는 모든 항목의 O가 0인지로 계산하는 것을 제안한다. 빈 발주는 승인할 수 없다.

아래 불변식은 위 정책을 채택한 첫 범위에서 지켜야 할 조건이다. 특히 초과 입고나 단위 정책을 바꾸면 관련 식과 검증도 함께 개정해야 한다.

| ID | 불변식 |
| --- | --- |
| I01 | 입고는 존재하고 입고 가능한 발주 항목에 연결된다. 연결된 주문 품목과 수령 품목은 같아야 한다. 발주 기반 입고의 공급사와 대상 발주 관계도 일치해야 한다. |
| I02 | 각 입고 수량은 양수이며, 비교·집계하는 수량은 같은 기준 단위다. |
| I03 | 확정 입고와 잔량 취소를 합쳐 주문량을 넘을 수 없다. 현재 입고 내 같은 발주 항목의 여러 행도 합산해서 검사한다. |
| I04 | 작성 중인 입고와 취소된 입고는 R 및 순재고 증가에 기여하지 않는다. 유효한 확정 입고만 한 번 반영된다. |
| I05 | 입고 확정 시 입고 상태, 재고 증가, 이동 기록 및 유지하는 집계값은 모두 성공하거나 모두 실패한다. |
| I06 | 같은 입고의 확정 재요청은 추가 효과가 없다. 같은 입고의 취소 재요청도 추가 차감이 없다. 취소된 입고를 같은 식별자로 다시 확정하지 않는다. |
| I07 | 동시 확정과 잔량 취소에서도 I03이 지켜진다. 조회 후 검사만 하고 경쟁하는 저장을 그대로 허용해서는 안 된다. |
| I08 | 확정된 수령 사실을 직접 덮어쓰지 않는다. 취소는 원래 확정과 연결되고, 수량·로트·위치별 효과를 정확히 상쇄한다. 원본 이동 이력은 보존한다. |
| I09 | 입고 취소는 주문량 Q나 잔량 취소 C를 바꾸지 않는다. 잔량 취소는 실제 수령 R이나 재고를 줄이지 않는다. |
| I10 | 재고는 품목·위치·로트 기준으로 일관되게 반영한다. 유효한 위치와 상품의 보관 조건을 만족해야 한다. 재고량·예약량은 음수가 아니고 예약량은 현재고를 넘지 않는다. |
| I11 | 수령 현황은 원본 발주·잔량 취소·유효한 확정 입고로 설명 가능해야 한다. 별도 누적값과 원본이 어긋난 상태를 정상 처리 결과로 남기지 않는다. |

## 시나리오와 기대 결과

### S01. 발주 일부를 처음 받는다

- 전제: 발주 항목 Q=100, C=0, R=0이며 입고 가능한 상태다. 해당 위치·로트의 기존 재고는 0이다.
- 행동: 창고 담당자가 60개와 위치·로트를 작성한다. 작성만으로는 실적과 재고가 바뀌지 않는다.
- 확정: 품목·단위·보관 조건·잔량을 검사하고 입고를 확정한다.
- 결과: R=60, O=40, 해당 재고=60. 입고 원인을 추적할 이동 기록이 남는다. 발주 주문량은 100 그대로다.
- 적용: P01~P03, P08~P09, I01~I05, I10~I11.

### S02. 나머지를 다른 날 받는다

- 전제: S01 이후 R=60, O=40이다.
- 행동: 별도 입고로 40개를 확정한다. 로트 또는 위치는 첫 입고와 다를 수 있다.
- 결과: R=100, O=0. 두 입고의 이력과 각각의 재고 위치·로트가 유지된다. 전량 수령으로 판단하며 다른 항목도 충족됐을 때 발주 전체 종료가 가능하다.
- 적용: P03, P10, I03~I05, I10~I11.

### S03. 남은 수량보다 많이 들어온다

- 전제: Q=100, R=60, C=0, O=40이다.
- 행동: 45개를 확정하려 한다.
- 결과: 초과 5개와 가능한 잔량 40개를 알리고 확정을 거절한다. R=60, O=40, 재고와 이동 기록은 그대로다. 자동으로 40개만 확정하지 않는다. 실제 인수할 수량은 현장에서 재확인한다.
- 적용: P05, P08, I03, I05.

### S04. 남은 물량을 더 받지 않기로 한다

- 전제: Q=100, R=60, C=0이다.
- 행동: 구매 담당자가 사유를 남기고 잔량 40개를 취소한다.
- 결과: Q=100, R=60, C=40, O=0. 재고는 바뀌지 않는다. 전량 수령과 구별되는 종료 가능 상태다. 41개 취소는 거절한다.
- 일부만 10개 취소하면 C=10, O=30으로 추가 입고를 기다린다.
- 적용: P04, P10, I03, I07, I09, I11.

### S05. 잘못 확정한 입고를 취소한다

- 전제: 60개 입고가 확정됐고 후속 재고 처리가 없음을 확인할 수 있다.
- 행동: 창고 담당자가 사유를 남기고 해당 입고 확정을 취소한다.
- 결과: 원래 재고 반영을 상쇄하고 유효 수령량에서 60을 제외한다. 원래 기록과 취소 기록을 보존한다. 정확한 수량은 새 입고로 등록한다.
- C=0이었다면 취소 후 R=0, O=100이다. 이미 C=40이었다면 R=0, C=40, O=60이다. 과거에 O=0이었더라도 현황을 다시 계산한다.
- 거절 조건: 후속 예약·이동·소비가 있거나 그 유무를 검증할 수 없으면 단순 취소를 허용하지 않는다. 후속 작업을 되돌리는 절차는 별도 요구사항이다.
- 적용: P06~P07, I04~I06, I08~I11.

### S06. 네트워크 재시도로 같은 확정이 다시 들어온다

- 전제: 동일 입고 ID로 60개 확정이 이미 성공했다.
- 행동: 응답을 받지 못한 사용자가 같은 입고의 확정을 다시 요청한다.
- 결과: 기존 확정 결과를 확인할 수 있고 R·재고·이동 기록은 추가되지 않는다. 취소 재시도도 동일하다.
- 한계: 서로 다른 입고 ID로 같은 실물 수령을 중복 등록하는 문제까지 이 규칙이 해결하지는 않는다. 외부 납품 식별자 등은 미결정이다.
- 적용: I06.

### S07. 두 작업이 같은 잔량을 동시에 사용한다

- 전제: Q=100, R=60, C=0, O=40이다.
- 행동 A: 서로 다른 두 입고가 각각 30개 확정을 요청한다.
- 결과 A: 하나가 성공하면 다른 하나는 잔량 10개 기준으로 거절된다. R=120이 될 수 없다.
- 행동 B: 입고 30개 확정과 잔량 40개 취소가 경쟁한다.
- 결과 B: 먼저 성공한 작업 결과를 반영해 다른 작업을 재검사한다. 두 작업이 모두 원래 잔량 40을 사용해서 성공해서는 안 된다.
- 적용: I03, I07. 잠금·버전 검사 등 구현 수단은 별도 결정한다.

### S08. 잘못된 위치 또는 단위가 입력된다

- 행동: 냉장 품목을 허용하지 않는 위치로 확정하거나, 기준 단위 EA에 BOX 수량을 그대로 입력한다.
- 결과: 확정을 거절하고 입력을 수정할 수 있게 한다. 잘못된 단위끼리 숫자만 더하거나 비교하지 않는다.
- 한 입고의 여러 항목 중 하나라도 실패하면 전부 미확정으로 남고 재고 효과는 없다.
- 적용: P08~P09, I01~I03, I05, I10.

## 진리표와 상태 결정표

참(T)과 거짓(F)의 조합을 빠짐없이 검토한다. 아래 표 역시 정책 초안이며 현재 구현의 동작 표가 아니다. 조건을 묶은 진리표는 업무 판단의 조합을 나타내며, 묶음 안의 개별 검사까지 모두 열거한 것은 아니다. 권한 확인은 모든 명령의 선행 조건이다.

### 1. 입고 확정 요청의 상태별 처리

확정 재시도는 신규 확정과 구분한다. 이미 성공한 확정을 현재 잔량으로 다시 검사하면, 첫 처리로 잔량이 줄어 정상 재시도가 실패할 수 있다.

| 현재 입고 상태 | 확정 요청 처리 | 새 수량 효과 |
| --- | --- | --- |
| 존재하지 않음 | 대상 없음으로 거절 | 없음 |
| 작성 중 | 아래 신규 확정 진리표로 판단 | 허용 시 한 번 |
| 확정됨 | 저장된 확정 결과 확인·반환 | 없음 |
| 취소됨 | 재확정 거절, 새 입고 작성 필요 | 없음 |

이미 확정된 입고의 내용을 재시도 요청으로 수정할 수 없다. 확정 명령은 저장된 입고를 대상으로 한다. 동시 확정 요청도 최종적으로 같은 상태 분기와 한 번의 효과만 갖도록 처리해야 한다.

### 2. 신규 입고 확정 진리표

작성 중 입고에 대해 다음 세 조건을 정의한다.

- E: 대상 발주가 승인·발송 조건을 충족하고, 발주 항목·품목·공급사 연결이 유효하다.
- V: 입고 항목이 하나 이상이고, 모든 수량이 양수이며 단위·로트 등 필수 정보·보관 위치 조건이 유효하다. 로트 필수 정책 등 미결정 규칙은 채택 후 구체화한다.
- W: 현재 입고 내 동일 발주 항목의 수량을 합산한 q가 각 항목의 최신 O 이하이다. 대상·수량이 잘못되어 비교 자체가 불가능하면 W를 참으로 취급하지 않는다.

업무상 신규 확정 허용 = E ∧ V ∧ W.

| E | V | W | 신규 확정 허용 | 신규 저장 효과 |
| --- | --- | --- | --- | --- |
| F | F | F | F | 없음 |
| F | F | T | F | 없음 |
| F | T | F | F | 없음 |
| F | T | T | F | 없음 |
| T | F | F | F | 없음 |
| T | F | T | F | 없음 |
| T | T | F | F | 없음 |
| T | T | T | T | 입고 확정·재고·이동 기록·유지하는 집계를 함께 반영 |

논리 조합을 모두 표시했으며 일부 조합은 실제 입력에서 도달하지 않을 수 있다. 표의 거절 이유는 하나로 제한하지 않는다. 충족하지 못한 검사 조건을 설명할 수 있어야 한다. 업무상 허용이어도 저장 실패 시에는 I05에 따라 전체를 되돌린다.

W는 경쟁하는 확정·잔량 취소와 일관된 최신 상태에서 보호되어야 한다. 트랜잭션 시작 전에 읽은 수치에 이 표를 적용하는 것만으로 I07이 보장되지는 않는다.

### 3. 수령 현황 결정표

전제는 Q > 0, C ≥ 0, R ≥ 0, O = Q - C - R ≥ 0이다. 이 전제를 깨는 값은 아래 표로 정상 상태를 부여하지 않고 불변식 위반으로 처리한다.

| R > 0 | O > 0 | 품목의 현황 | Q=100일 때 예시 | 종료 가능 |
| --- | --- | --- | --- | --- |
| F | T | 미수령, 받을 잔량 있음 | R=0, C=0, O=100 | F |
| F | F | 수령 없이 주문 전량 취소 | R=0, C=100, O=0 | T |
| T | T | 일부 수령, 받을 잔량 있음 | R=60, C=0, O=40 | F |
| T | F | 수령 및 취소로 잔량 해소 | R=60, C=40, O=0 또는 R=100, C=0, O=0 | T |

마지막 행에서 C=0이면 전량 수령이고, C>0이면 일부 수령 후 잔량 취소다. 따라서 O=0만으로 전량 수령이라고 판단하지 않는다. 종료 가능은 계산 결과이며 CLOSED라는 별도 상태를 저장하거나 최종 마감 명령을 실행한다는 뜻은 아니다.

발주 전체 종료 가능 = 발주 항목이 하나 이상 있음 ∧ 모든 항목에서 O=0.

### 4. 잔량 취소 경계값 결정표

발주가 해당 취소를 허용하는 상태이고 담당자 권한·사유가 유효하다는 전제에서, 취소 요청량 x를 최신 O와 같은 단위로 비교한다.

| 수량 조건 | 허용 | 결과 |
| --- | --- | --- |
| x ≤ 0 | F | 변화 없음 |
| 0 < x < O | T | C는 x 증가, O는 x 감소, R·재고는 유지 |
| 0 < x = O | T | C는 x 증가, O=0, R·재고는 유지 |
| x > O | F | 변화 없음 |

O=0이면 양수의 잔량 취소는 모두 거절된다. 잔량 취소가 먼저 확정됐다면 경쟁 중인 입고는 줄어든 O로 검사하고, 입고가 먼저 확정됐다면 취소는 줄어든 O로 검사한다.

### 5. 입고 확정 취소 진리표

먼저 존재하지 않는 입고와 작성 중 입고의 확정 취소는 거절한다. 이미 취소된 입고는 기존 취소 결과를 확인하며 추가 차감하지 않는다. 작성 중 입고의 삭제는 다른 명령이다.

현재 확정 상태이고 권한·사유가 유효한 입고에 대해 다음을 검사한다.

- H: 해당 입고 재고에 후속 처리가 없음을 검증했다. 유무를 알 수 없으면 F다.
- B: 원래 위치·로트별 효과를 정확히 상쇄할 수 있으며, 상쇄 후 재고량·예약량과 수량 불변식을 만족한다.

신규 확정 취소 허용 = H ∧ B.

| H | B | 취소 허용 | 결과 |
| --- | --- | --- | --- |
| F | F | F | 변화 없음 |
| F | T | F | 현재 재고가 충분해도 후속 처리 조건 때문에 거절 |
| T | F | F | 원래 효과를 안전하게 상쇄할 수 없어 거절 |
| T | T | T | 취소 상태·반대 이동·재고·유지하는 집계를 함께 반영 |

### 6. 표를 검증에 사용하는 방법

신규 확정 진리표의 8개 조합과 취소 진리표의 4개 조합은 논리 검토 항목이다. 실제로 도달할 수 있는 조합을 검증하고, E·V·W의 내부 검사도 별도로 확인한다. 특히 q=0, q=O, q>O, O=0, 동일 발주 항목이 여러 입고 행에 나뉜 경우를 포함한다.

표는 단일 요청의 판단을 설명한다. 저장 중 실패, 동일 요청의 재시도, 서로 다른 요청의 동시 실행은 S06·S07 및 저장소 검증으로 따로 확인해야 한다.

## 첫 애플리케이션 흐름과 검증 기준

첫 구현 대상은 S01이다. 입고 식별자로 작성 내용을 조회하고, 필요한 발주 조건·현재 잔량·상품·위치 정보를 확보한 뒤, 검증과 입고 확정·재고 증가·이동 기록 생성을 처리한다. 별도 수령 집계값을 유지한다면 같은 성공 경계에 포함한다.

S01 구현을 완료했다고 판단하기 전에는 실패 시 부분 저장이 없는지, 확정 재시도가 중복 반영되지 않는지, 동시 확정이 잔량을 초과하지 않는지도 검증한다. 입고 작성 CRUD만으로 완료 처리하지 않는다.

수량 변화, 저장 원자성, 중복 처리, 동시성은 실제 저장소를 사용하는 검증이 필요하다. 도메인 메서드 단독 테스트만으로 시스템 보장을 주장하지 않는다. 이 문서 작성 시에는 코드 변경·빌드·테스트를 하지 않았다.

## 기존 코드와 연결해서 검토할 점

- PO.applyReceipt()와 POLine.receivedQty: 호출부가 없는 예상 책임이다. 원본 입고와 집계값의 관계를 정한 뒤 유지·이동·대체 여부를 결정한다.
- PO의 PARTIALLY_RECEIVED/CLOSED: 수령 현황과 발주 종료 의사가 섞였는지 검토한다. 현재 전량 수령을 마감으로 연결한 규칙을 확정 요구사항으로 간주하지 않는다.
- GoodsReceipt와 GoodsReceiptLine: 작성 모델은 있으나 확정·재고 연결 흐름은 없다.
- StockQuant, StockMove, Location.canStore(): 시나리오의 후보 구성요소다. 기존 코드가 위 불변식을 충족한다고 가정하지 않는다.
- OverReceivePolicy: 초과 허용 등록과 객체 복원의 검증이 일치하지 않는 부분이 있다. 정책 재도입 시 전체 경로를 함께 검토한다.
- Quantity: 현재 단위 종류만 확인한 뒤 숫자를 더하는 경로가 있으므로 I02를 충족하는지 확인해야 한다.

## 다음에 결정할 사항과 제외 범위

1. 입고 확정·취소·잔량 취소를 누가 실행할 수 있는지, 역할과 권한을 어떻게 검증할지.
2. 잔량 취소를 철회하거나 승인된 주문 조건을 변경하는 절차. 첫 범위에서는 지원하지 않는다.
3. CLOSED가 별도 업무 마감인지, 계산된 종료 현황인지. 최종 마감 후 정정 규칙도 함께 결정한다.
4. 입고 취소에 필요한 후속 재고 처리 추적 방식. 동일 품목·로트의 재고가 합쳐진 경우 단순 잔량 검사로 대체하지 않는다.
5. 유통기한 필수 대상과 입고 가능한 잔여 기한. 온도대·분류만으로 이를 추론하지 않는다.
6. 납품서 등 외부 식별자를 통한 중복 수령 등록 방지.
7. 초과 입고 허용, 단위 환산, 검수·격리, 반품, 출고 예약의 실제 흐름.
8. 무발주 입고와 발주 미확인 입고의 구분 및 사후 연결. 사후 연결이 재고를 다시 증가시켜서는 안 된다는 방향만 남기고 이번 범위에서 제외한다.
9. 발주 수령 현황을 조회 시 계산할지, 별도 집계로 저장할지. 선택 시 동시 확정과 잔량 취소의 불변식 보호 방법을 함께 결정한다.
